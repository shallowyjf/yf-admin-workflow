# 城市生命线 SaaS 权限系统与工单中心需求设计说明书

版本：V0.4（I26 权限模型简化）

场景：供水、排水、燃气、供热、道路城市生命线建设与运营

状态：I01–I26 已形成可运行 Demo；I26 取消岗位授权维度

## 1. 产品目标

平台面向一个城市或城市级客户租户，在同一租户内承载供水、排水、燃气、供热、道路五类生命线系统。每个系统管理各自的施工工程项目，甲方、监管方、施工方和软件平台方在同一项目空间内协作，通过统一身份、角色权限、项目数据范围、流程任务和工单中心形成闭环。

平台必须同时满足：

- 所有身份从统一登录中心提交用户名和密码，界面与登录协议不要求租户编码；
- 平台 Root 与租户用户使用相互独立的身份和会话，Root 先选择城市，不直接继承租户业务权限；
- 不同租户的数据、账号、会话和业务资源不可互访；
- 同租户下不同生命线系统的功能入口和业务数据可隔离；
- 组织只表达真实单位与部门，不用组织节点模拟工程项目；
- 项目是数据权限载体，同一用户可通过不同组织成员关系参加多个项目；
- 角色决定“能做什么”，组织与项目共同决定“能在哪些数据上做”；
- 甲方领导可看多系统、多项目汇总，监管方可监督，施工方可处置，平台方只获得约定的运维权限；
- 工单的创建、派发、认领、处理、复核、关闭全过程可追溯。

## 2. 核心概念与边界

| 概念 | 业务含义 | 是否承载数据权限 | 当前状态 |
| --- | --- | --- | --- |
| Tenant 租户 | 一个城市/客户的 SaaS 隔离边界 | 是，最高隔离边界 | I19 已实现 IAM 边界 |
| Application 生命线系统 | 供水、排水、燃气、供热、道路产品域 | 是，系统入口与业务域边界 | I21 已实现用户入口授权与会话切换 |
| Organization 组织 | 甲方、监管方、施工方、平台方及其真实部门 | 是，实体组织范围 | I19 已实现，I20 重构种子 |
| Project 工程项目 | 某生命线系统下的具体建设/改造项目 | 是，主要业务数据空间 | I21 已实现配置与成员角色授权 |
| User 用户 | 可登录身份 | 否，身份主体 | 已实现 |
| Membership 组织成员关系 | 用户属于某真实组织，可多组织 | 是，组织内角色绑定点 | 已实现 |
| Role 角色 | 功能权限集合 | 间接，通过授权与范围生效 | 已实现 |
| Permission 权限 | 稳定动作编码 | 否，表达动作能力 | 已实现 |
| WorkOrder 工单 | 项目内的业务事件与处置对象 | 是，必须归属租户、系统、项目、组织 | I22 已绑定租户、系统与项目 |
| WorkflowTask 流程任务 | 工单节点的待办与认领对象 | 继承工单边界 | I22 已继承工单上下文并校验项目资格 |
| DataSpace 数据空间 | 城市公共、业务共享、系统私有、项目协作、汇总或模型沙箱空间 | 是，承载非项目及跨系统数据边界 | I24 规划 |
| BusinessResource 业务资源 | 数据集、GIS 图层、设施、API、文件、指标、模型和结果 | 是，系统内部数据授权对象 | I24 规划 |
| ResourcePolicy 资源策略 | 主体对资源动作、范围、字段和条件的允许或拒绝策略 | 是，细粒度授权规则 | I24 规划 |
| ApplicationRoleGrant 应用角色授予 | 用户组织成员在指定系统中的角色 | 是，解决同人在不同系统角色不同 | I24 规划 |
| ServiceAccount 服务账号 | 系统间数据同步、模型计算和 API 调用身份 | 是，非人主体的最小授权 | I26 规划 |

目标授权判定公式：

```text
允许访问 = 同一租户
        ∩ 租户已开通生命线系统
        ∩ 用户具备系统入口权限
        ∩ 应用级/项目级角色具备功能权限
        ∩ 项目成员/项目汇总范围
        ∩ 数据空间和具体资源策略
        ∩ 组织/项目/行级/空间范围
        ∩ 字段、敏感等级和对象关系
        ∩ 状态、用途、时间和环境条件
        ∩ 不存在优先级更高的显式拒绝
```

前端隐藏菜单和按钮仅用于体验，所有接口必须重复执行服务端鉴权。请求中传入的租户、系统、项目或组织 ID 不可信，服务端必须从会话与资源自身归属重新计算。

### 2.1 分层入口与默认落点

```text
平台 Root 登录 → 选择城市租户 → 该租户管理员会话 → 租户应用导航
租户管理员登录 ───────────────────────────────→ 租户应用导航
现场工程人员登录 ─────────────────────────────→ 工单中心
```

- 平台 Root 使用独立的平台用户表和会话，只具备列出租户、选择租户的控制面能力；
- 租户用户使用平台全局唯一的 `login_name` 自动定位所属租户；租户内 `username` 继续作为业务账号和组织显示标识；
- 多城市存在同名业务账号时采用城市前缀，例如 `haizhou.admin`、`yunzhou.admin`，禁止依靠密码或遍历租户猜测身份；
- 选择租户后，由受信任的服务端入口创建该租户 `admin` 会话，租户 RBAC 仍照常生效；
- 租户应用导航显示权限中心、工单中心和用户实际获授权业务方向的驾驶舱；
- 同一业务方向存在多个系统时合并为一个驾驶舱卡片，但卡片内仅展示获授权系统和项目；
- 驾驶舱为演示级静态态势页面，入口授权、系统数和可见项目数来自真实授权数据；
- 管理与监督角色默认进入应用导航，施工、调度、处置等一线角色默认进入工单中心。

## 4. 默认权限配置

### 4.1 权限命名

- 平台与 IAM：`system:<resource>:<action>`；
- 项目：`project:<resource>:<action>`；
- 工单：`workorder:<action>`；
- 进入 I21 后，系统专属权限可使用 `<application>:<resource>:<action>` 命名空间；
- 公共工单权限只用于所有生命线系统语义完全一致的动作，不得用公共编码绕过系统隔离。

### 4.2 默认角色能力

| 角色 | 主要功能权限 | 默认范围 |
| --- | --- | --- |
| 系统管理员 | 全部 IAM、系统、项目、工单权限 | ALL |
| 甲方领导 | 系统查看、项目查看、全部项目汇总、工单查看 | ALL，但敏感明细仍需独立权限 |
| 甲方调度员 | 项目查看、进度查看、工单创建/派发/催办/复核/关闭 | 当前组织及下级 |
| 施工项目经理 | 项目维护、参与组织/成员配置、工单创建/派发/转派/关闭 | 当前组织及下级，并受项目成员资格约束 |
| 施工处置人员 | 项目查看、工单查看/认领/处理/转派/评论/附件 | SELF，并受项目成员资格约束 |
| 监管复核人员 | 项目与进度查看、工单查看/评论/催办/复核/关闭 | 当前组织，并受监管项目范围约束 |
| 平台运维人员 | 系统与项目查看、工单只读协作、IAM 审计查看 | ALL 仅代表获授权租户内；不得默认获得业务敏感字段 |
| 业务方向负责人 | 获授权系统内项目进度汇总、工单查看 | 当前组织及下级；系统入口可跨供水、排水等业务组合 |
| 单系统业务专员 | 单系统项目进度与工单查看 | 当前组织；即使同业务存在多个系统也只进入显式获授系统 |
| 业务甲方项目经理 | 项目进度维护、建单、派单、复核 | 当前组织及下级，并叠加系统入口与项目成员资格 |
| 工程监理工程师 | 进度、工单、复核和评论 | 当前组织及下级，并叠加监理项目成员资格 |
| 软件交付工程师 | 项目进度、工单协作、附件 | 当前组织及下级，并叠加软件交付项目成员资格 |

任何角色授权必须同时配置数据范围。高权限角色需要审批、有效期、职责分离和定期复核；I20 Demo 先提供默认矩阵展示，治理能力在 I25 完成。

## 5. 项目数据权限

项目必须包含：`tenant_id`、`application_id`、项目编码、名称、状态、起止日期。项目参与组织必须包含参与方类型；项目成员必须引用有效的用户组织关系和租户内角色。

项目可见性：

- 具有 `project:progress:view-all` 的甲方领导或系统管理员可查看租户已开通系统下的全部项目；
- 其他具有 `project:view` 的用户只能查看自己作为有效成员参加的项目；
- 用户、组织、角色、系统订阅、项目或项目成员任一停用后，不得获得新的业务访问；
- 项目归档后保留历史只读与审计，禁止新建或提交工单；
- 项目参与组织不是实体组织成员关系的替代品；项目成员必须来自参与组织或其明确授权的下级组织；
- 跨系统、跨项目访问必须显式授权，禁止根据前端“当前项目”直接放行。

## 6. 多系统隔离

租户开通系统使用 `sys_tenant_application`。业务表最终必须同时保存 `tenant_id`、`application_id`、`project_id` 和 `owner_org_id`。后端读取资源后校验四级归属，缓存键、对象存储路径、消息主题和搜索索引也必须包含相同隔离维度。

身份、组织、角色和基础字典属于 COMMON 共享域；供水、排水、燃气、供热、道路业务明细属于各系统私有域。城市级领导看板通过授权后的汇总读模型读取，不直接跨库扫描全部原始工单与敏感附件。

生产建议采用混合隔离：控制面共享库；标准租户使用共享 PostgreSQL + RLS；高敏租户或系统可使用独立 Schema/数据库实例。应用层过滤与数据库 RLS 均必须存在。

## 7. 系统数据权限

### 7.1 权限分层

系统入口只控制用户能否进入系统，不自动授予系统内的数据。系统数据权限必须分为：

1. **入口权限**：是否进入供水 GIS、DMA、水力模型等具体系统；
2. **应用功能权限**：用户在不同系统中分别具备查看、编辑、运行、发布等动作；
3. **数据空间权限**：访问城市公共、业务共享、系统私有、项目协作、汇总或模型沙箱空间；
4. **资源权限**：访问具体图层、数据集、设施、API、文件、指标、模型和结果；
5. **数据细节权限**：限定行、字段、行政区、DMA、项目红线、资产组、时间和敏感等级；
6. **使用权限**：区分发现、预览、查询、写入、下载、导出、发布、共享和 API 调用；
7. **流程任务权限**：涉及工单或审批时仍需通过当前任务处理权。

### 7.2 应用级角色

现有组织角色继续表达租户内基础职责，项目角色继续表达项目身份；新增 `ApplicationRoleGrant`，允许同一组织成员在不同系统中获得不同角色。例如同一用户在供水 GIS 中可编辑、在水力模型中只读、在 DMA 系统中可导出。

应用级角色不能替代系统入口或项目成员资格。系统入口、应用角色、项目角色、资源策略任一缺失时均不得扩大数据访问。

### 7.3 数据空间与资源

项目不再被视为所有数据的唯一容器：

| 数据空间 | 示例 |
| --- | --- |
| COMMON | 行政区划、组织、基础字典、统一编码 |
| DOMAIN_SHARED | 供水基础管网、排水设施目录 |
| APPLICATION_PRIVATE | DMA 监测明细、GIS 编辑数据 |
| PROJECT | 测绘成果、施工资料、项目工单 |
| AGGREGATE | 城市领导和业务方向授权汇总读模型 |
| MODEL_SANDBOX | 水力模型场景、参数、试算结果 |

所有业务资源必须保存租户、数据空间、来源系统、归属组织，并在适用时保存项目；资源层级不得跨租户。跨系统共享使用显式资源授权，不得通过相同业务方向、相同组织或省略 `application_id` 隐式共享。

### 7.4 资源策略与数据范围

功能权限使用稳定编码，具体数据使用资源策略绑定。资源策略主体支持用户、角色、组织、项目、应用和服务账号；资源策略包含动作、允许/拒绝、有效期、用途、行级/空间范围和字段策略。

现有 `ALL/ORG/ORG_AND_CHILD/SELF/CUSTOM` 继续用于组织树与工单。系统数据权限另行支持项目、行政区、DMA、GIS 图层、资产组、资源集合、时间范围、数据标签和对象关系。复杂条件必须使用受控结构，不允许在策略中保存任意 SQL。

### 7.5 字段、下载与导出

- 看得到目录不等于能预览数据；
- 能预览不等于能下载或导出；
- 能查询汇总不等于能查看原始明细；
- 无精确坐标权限时，后端返回泛化坐标或聚合结果，不得先返回原值再由前端隐藏；
- 字段策略支持可见、隐藏、脱敏、泛化、聚合和哈希；
- 下载、导出、发布和跨系统共享必须使用独立权限、有效期和审计。

### 7.6 GIS、水力模型与数据中心

GIS 权限至少覆盖驾驶舱、图层、设施增删改、空间查询、敏感坐标、数据导出及 WMS/WFS/WMTS/瓦片服务。水力模型权限至少覆盖模型查看/编辑、版本、场景、运行、结果、校准、导出、审批和发布，并落实编辑、运行、审批、发布职责分离。

水力模型读取 GIS 管网时使用服务账号和显式 `DataAccessGrant`，限定数据集、字段、区域、项目、用途和有效期；模型运行保存输入数据快照与授权快照，领取结果时再次实时鉴权。

采集数据、处理数据、模型输入快照、模型运行和模型结果必须作为独立资源授权。数据人员拥有监测数据的采集、清洗、质量和查询权限，不自动获得 `hydraulic:result:view`；模型运行权限也不自动授予结果查看或导出。数据血缘只描述派生关系，不传播权限。需要向数据人员或领导开放成果时，应发布单独的脱敏/汇总资源并再次授权。

权限中心负责策略和授权；数据中心负责目录、数据、质量、血缘和交付；工单与流程中心负责数据权限申请、审批、到期回收及数据质量问题处置。三者共享身份与资源上下文，但不得相互替代。

### 7.7 驾驶舱和数据出口

真实数据接入后，业务方向总览只读取授权汇总读模型，具体系统驾驶舱按 `application_id` 独立鉴权，每个指标、图层和下钻链接继续执行资源策略。只拥有供水水力模型入口不能因此读取供水 GIS 原始图层。

API、PostgreSQL RLS、GIS 服务、对象存储、查询引擎、搜索索引、缓存、消息主题和导出任务必须执行同一隔离维度。前端菜单或图层开关不能代替这些强制执行点。

详细模型、权限编码、API、审计、缓存和回归设计见 `docs/SYSTEM_DATA_PERMISSION_DESIGN.md`。

## 8. 工单与流程闭环

标准状态：

```text
DRAFT → PENDING_DISPATCH → PENDING_CLAIM → PROCESSING
      → PENDING_REVIEW → COMPLETED → CLOSED
```

允许驳回从 `PENDING_REVIEW` 返回 `PROCESSING`，原处理人仍有效时重新生成处理任务，否则进入重新派单。工单创建时固化租户、系统、项目、归属组织与创建人；派单目标必须是项目参与组织，候选人必须同时满足同租户、同系统、同项目、有效组织成员、项目成员角色和组织角色规则。

认领、处理、转派、复核时实时校验项目资格。成员退出、授权到期或项目归档后立即禁止新动作，但保留历史时间线。I22 已完成项目工单绑定；未初始化项目目录的历史单元测试保留兼容路径，一旦存在项目目录即启用严格项目校验。

## 9. 项目进度与领导看板

甲方领导查看多系统、多项目总体进度；甲方项目负责人查看单项目全貌；监管方查看其监管项目；施工项目经理查看项目和施工组织；员工查看本人任务。

项目进度不得简单使用工单完成率，建议采用里程碑加权：

```text
里程碑进度 = 已完成跟踪工单权重 / 全部跟踪工单权重
项目进度 = Σ(里程碑进度 × 里程碑权重)
```

汇总看板至少展示总体进度、里程碑、参与方完成率、处理中、待派单、待认领、待复核、逾期和 SLA 违约。汇总查看权限不自动授予敏感工单详情、附件下载或个人隐私字段权限。

## 10. 审计、安全与非功能要求

- 登录、租户/系统/项目切换、授权变化、项目成员变化、工单动作、附件下载和导入导出必须审计；
- 数据目录发现、查询、下载、导出、共享、GIS 编辑、模型运行/审批/发布和服务账号调用必须审计；
- 提供“用户为什么能访问该数据”的授权链解释；
- 认证安全包含密码策略、限速、锁定、Secure Cookie、CSRF、MFA/SSO 和密钥托管；
- 创建、认领、派单、复核、关闭和外部事件接入使用幂等键与并发控制；
- 附件使用对象存储、异步安全扫描、签名下载和下载审计；
- 通知使用 Outbox、重试、死信和多渠道适配；
- 提供结构化日志、Trace、指标、告警、备份恢复和 RPO/RTO 演练；
- SQLite 仅用于 Demo 与快速回归，生产使用 PostgreSQL。

## 11. 当前实现边界

I21 已实现系统入口和项目授权，I22 已把工单流程纳入租户/系统/项目边界。I23 按演示目标增加了四阶段里程碑、加权计划/实际进度、多系统汇总、角色只读/更新权限和审计；不将其声明为实时生产驾驶舱。

当前代码能够判定用户能否进入系统、参加项目并查看或处理项目工单，但尚未实现应用级角色授予、数据空间、统一业务资源、字段/空间策略、服务账号、跨系统数据授权和数据出口强制执行。因此静态驾驶舱不得被解释为已经具备真实 GIS、水力模型或数据中心数据权限。

权威后续路线见 `docs/iterations/ROADMAP_I20_I25.md` 与 `docs/iterations/ROADMAP_I24_I28_DATA_PERMISSION.md`。每轮必须包含模型/迁移、服务端鉴权、种子幂等、跨边界负向用例、API/UI 人工验收和全量质量门禁。
