# I16：工单转派、协作评论与催办

## 变更摘要

本轮启动 P1 可用业务产品优先路线，补齐工单进入“处理中”后的协作断点。工单管理员或当前处理人可把工单转给当前组织内具有 `workorder:handle` 权限的有效用户；任何转派同时更新 WorkOrder 与活跃 WorkflowTask。具备相应权限的可见用户还可追加评论或对在途工单催办。

## 业务规则

- 转派只允许 `PROCESSING`，禁止转给当前处理人或无有效处理权限的用户。
- 转派遵守 `workorder:transfer` 对应 DataScope；SELF 范围的原处理人转出后立即失去该工单可见性。
- 评论内容必填、去除首尾空格且不超过 1000 字；允许对已关闭工单补充审计说明。
- 催办只允许待派单、待认领、处理中和待复核状态，内容必填。
- 新增稳定权限 `workorder:comment`、`workorder:urge`，Seed 权限数为 36，角色授权与 DataScope 数均为 60。

## API 与页面

- `POST /api/workorders/{id}/transfer`
- `POST /api/workorders/{id}/comments`
- `POST /api/workorders/{id}/urge`
- 工单详情新增转派目标选择、协作评论、催办表单和中文动作标签。

## 持久化与一致性

无需数据库迁移。工单协作事件复用 `wo_action`，Workflow 转派审计复用 `wf_task_history`。Workflow 提交事务时同时提交工单处理人、工单动作和任务处理人；失败时统一回滚。

## 回归范围

- 服务层：权限、数据范围、目标处理资格、状态、文本校验和完整时间线。
- Workflow：CLAIMED 任务转派、候选规则更新和前后处理人审计。
- API：评论、催办、非法目标、转派后任务可见性与后续处理。
- 页面：动作按钮、目标用户、表单提交和中文协作时间线。

## 验收结果

- 全量质量门禁通过：`118 passed`，覆盖率 `90.93%`，Ruff、敏感信息和 Alembic 漂移检查通过。
- 真实页面完成 COMMENT、URGE、TRANSFER 三类操作，时间线同时展示中文标签和稳定动作编码。
- 转派后工单 `current_assignee_id` 从李四变为赵六，赵六的活跃 HANDLE 任务为 `CLAIMED`，处理人同步一致。
