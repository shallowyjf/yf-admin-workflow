# I03：功能权限与数据范围

## 本轮目标

在 I02 多组织角色模型上增加功能权限字典、角色授权和按功能配置的数据范围，为后续工单查询与流程任务鉴权提供稳定边界。

## 已实现

- `sys_permission`、`sys_role_permission`、`sys_role_data_scope` 三张表及 Alembic `0003_i03` 迁移。
- 8 个 `workorder:*` 权限码及五类演示角色策略的幂等种子数据。
- `PermissionService.has_permission()`：只解析用户在活动组织内的有效角色授权。
- `WorkOrderScopeFilter`：结构化表达 `ALL`、组织集合和本人条件。
- `ORG`、`ORG_AND_CHILD`、`SELF`、`CUSTOM` 范围解析；多角色范围按并集合并且 `ALL` 优先。
- fail-closed：无权限、无范围或无有效活动组织关系均返回无数据。

## 回归覆盖

| 编号 | 场景 | 预期 |
| --- | --- | --- |
| IAM-004 | 父组织角色配置 `ORG_AND_CHILD` | 包含本组织和有效下级，不含父级与兄弟组织 |
| IAM-005 | 父组织角色配置 `ORG` | 仅包含活动组织，不包含下级 |
| IAM-006 | 角色配置 `SELF` | 过滤器只携带当前用户 ID |
| IAM-007 | 用户能查看但没有 `workorder:dispatch` | 可见范围不赋予派单权限 |
| I03-005 | 用户在另一组织没有相同角色 | 活动组织切换后授权不串用 |
| I03-006 | 角色配置 `CUSTOM` | 仅包含配置的组织 ID |
| I03-007 | 种子执行两次 | 权限、授权和范围记录数不增加 |
| I03-008 | 迁移升级/回退 | 三张 I03 表可创建并完整移除 |
