# I20：城市生命线系统与工程项目权限展示基线

## 目标

将 I19 的通用 SaaS 权限基线落到城市生命线业务场景：一个租户开通供水、排水、燃气、供热、道路多套系统；每套系统对应独立施工工程项目；甲方、监管方、施工方、平台方使用真实组织协作；项目作为数据权限载体。

## 本轮完成

- 新增 `sys_application` 与 `sys_tenant_application`，建立系统目录和租户系统订阅；
- 新增 `pm_project`、`pm_project_org`、`pm_project_member`；
- 重构默认组织为甲方、监管方、施工方、平台方四棵实体组织树；
- 新增甲方领导、监管人员、平台运维人员及对应角色岗位；
- 增加项目查看、维护、成员/组织配置和进度查看权限；
- 默认生成五套生命线系统、五个工程项目、20 条项目参与组织关系和 31 条项目成员角色关系；
- 提供 `/api/lifeline/structure` 与 `/lifeline`，展示系统—项目—组织—成员角色—权限矩阵；
- 甲方领导/系统管理员查看全部项目，普通项目成员只看本人参加项目；
- 空库迁移、种子幂等、租户隔离、旧 IAM/工单流程继续纳入回归。

## 数据结构

| 表 | 说明 |
| --- | --- |
| `sys_application` | 平台级生命线系统稳定目录 |
| `sys_tenant_application` | 租户开通的系统入口 |
| `pm_project` | 系统下的工程项目和数据权限空间 |
| `pm_project_org` | 项目参与组织及 OWNER/REGULATOR/CONTRACTOR/PLATFORM 身份 |
| `pm_project_member` | 项目内用户组织成员关系与项目角色绑定 |

## 自动化回归

1. I20 Migration 可从 I19 升级到 Head，模型与迁移无漂移；
2. IAM 与项目 Seed 连续执行两次不重复；
3. 默认数据精确包含 5 个系统、5 个项目、4 类参与方；
4. `admin` 可查看全部项目和完整默认角色权限矩阵；
5. `lisi` 只能查看其参加的供水、排水、供热项目；
6. I19 跨租户同名账号与 IAM 查询隔离继续通过；
7. 既有组织 CRUD、候选人解析、DMA 工单流转继续通过；
8. 全量 Ruff、敏感信息检查、Warnings-as-errors、覆盖率和 Alembic Check 通过。

## 人工验收

1. 使用 `DEMO / admin / Demo@123456` 登录；
2. 打开 `/lifeline`，确认显示供水、排水、燃气、供热、道路五类系统；
3. 每个系统显示一个默认施工工程项目和甲方、监管方、施工方、平台方；
4. 页面下方显示默认角色权限矩阵；
5. 使用 `lisi` 登录，仅应显示供水、排水、供热三个本人参与项目；
6. 打开组织管理，确认项目没有出现在组织树中，四类实体组织独立存在；
7. 回到工单中心完成原 DMA 创建—派单—认领—处理—复核—关闭流程。

## 已知边界

本轮提供项目权限载体和只读展示，既有工单尚未增加 `tenant_id/application_id/project_id`，系统入口切换、项目 CRUD 和项目级工单强制隔离在 I21–I22 完成。
