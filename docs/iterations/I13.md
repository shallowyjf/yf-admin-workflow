# I13：角色授权与 DataScope 闭环

## 1. 变更摘要

角色管理从只读展示升级为完整授权闭环。系统管理员可以通过 REST API 或页面新增、编辑、启停角色，并一次性替换角色的 Permission + DataScope 配置。授权和角色状态变化由现有认证 Profile 在每次请求中重新计算，无需用户重新登录。

## 2. 新增/修改文件

- 新增 `app/iam/role_admin_service.py`：角色生命周期、原子授权、数据范围校验、安全保护和审计。
- 新增 `app/iam/role_router.py`：角色 REST API。
- 扩展 IAM Schema/Repository：角色详情和授权响应、按 ID 加载完整角色聚合。
- 修改 Dashboard Router/Service、角色模板和 IAM 样式：可操作授权矩阵。
- 扩展 Seed：四个角色管理权限默认只授予 `SYSTEM_ADMIN`。
- 新增 `tests/test_role_admin.py`，扩展页面、Seed 和健康检查回归。

## 3. 数据库迁移说明

本轮没有数据库结构变化，不新增 Alembic Revision。授权继续使用 `sys_role_permission` 与 `sys_role_data_scope`，CUSTOM 组织 ID 存入 `scope_config.org_ids`。

Seed 新增以下权限，并且只授予 `SYSTEM_ADMIN`：

- `system:role:create`
- `system:role:update`
- `system:role:status`
- `system:role:authorize`

## 4. 公开 Service/API 变化

- `GET /api/roles`：角色及 Permission + DataScope 列表。
- `GET /api/roles/{id}`：角色授权详情。
- `POST /api/roles`：新增角色。
- `PUT /api/roles/{id}`：编辑角色名称和类型。
- `POST /api/roles/{id}/status`：启停角色。
- `PUT /api/roles/{id}/authorization`：原子替换角色的全部权限及数据范围。

角色编码创建后保持稳定，不提供物理删除。每个已授予权限必须同时有且只有一个 DataScope；撤销权限时同步清理对应 DataScope。CUSTOM 只接受存在、启用且不重复的组织。为防止管理入口被误锁死，`SYSTEM_ADMIN` 不允许停用，并必须保留角色查看、新增、编辑、启停和授权权限。

人工验收：使用 `admin / Demo@123456` 打开 <http://127.0.0.1:8000/iam/roles>，新建临时角色并为 `workorder:view` 选择 CUSTOM 和指定组织；再到用户管理把该角色配置给一个测试账号。保持测试账号会话不退出，修改授权或停用角色，刷新页面确认权限在下一次请求即时变化。

## 6. 与设计文档是否存在偏差

没有修改 Permission + DataScope 核心模型。设计资料中的分步授权接口收敛为一个原子替换接口，原因是分步写入会产生“已有 Permission 但缺少 DataScope”的无效中间状态；页面仍可一次编辑整张授权矩阵。
