# I09：DMA 完整业务闭环

## 本轮目标

按设计资料的标准演示脚本，把 IAM、CandidateResolver、WorkflowTask、WorkOrder 和操作时间线串联成一个可重复执行、可自动验收的 DMA07 压力异常处置闭环。

## 标准场景

1. 王五创建“DMA07 压力异常”工单并提交。
2. 王五派给管网运行部，候选规则为 `ORG_ROLE(PIPE_OPERATION, REPAIRER)`。
3. 李四和赵六都能看到同一个候选任务，候选用户集合精确等于二人。
4. 李四认领成功，赵六竞争认领返回 409。
5. 李四提交处理结果，王五复核通过并关闭。
6. 工单最终状态为 `CLOSED`，调度中心仍能查看详情和完整时间线。

## 已实现

- 新增 `python -m app.demo.dma_workflow_demo`，可在当前演示数据库重复生成并执行一条标准 DMA 闭环。
- 新增独立 FastAPI TestClient E2E，全部动作通过真实 HTTP、Session Cookie、SQLite Repository 和 Seed 数据完成，不用 Mock 替代关键规则。
- 精确断言处理候选人为 `lisi`、`zhaoliu`，且二人看到的是同一任务。
- 精确断言完整状态路径：`DRAFT → PENDING_DISPATCH → PENDING_CLAIM → PROCESSING → PENDING_REVIEW → COMPLETED → CLOSED`。
- 精确断言完整时间线：`CREATE → SUBMIT → DISPATCH → CLAIM → SUBMIT_RESULT → APPROVE → CLOSE`。
- DataScope 的组织条件同时匹配 `current_org_id` 和 `owner_org_id`，派单后原所属调度中心仍能查看、复核和关闭。

本轮没有数据库结构变化，不新增 Alembic Revision，也没有提前实现 I10 页面。

## 人工验收

```powershell
.\.venv\Scripts\python.exe -m app.demo.dma_workflow_demo
```

输出必须满足：

- `candidate_usernames` 为 `lisi`、`zhaoliu`；
- `second_claim_conflict` 为 `true`；
- `final_status` 为 `CLOSED`；
- `timeline_actions` 严格包含 7 个标准动作且顺序正确。

也可以在 Swagger 中按相同步骤逐项调用：<http://127.0.0.1:8000/docs>。
