# I05：CandidateResolver

## 本轮目标

实现 USER、ROLE、ORG、ORG_ROLE、ORG_POSITION 五类可插拔候选人解析器与 Registry，并验证停用过滤和结果去重。

## 已实现

- IAM 公开 `IdentityQueryService`，集中完成有效用户、组织成员、角色和岗位查询。
- workflow `IdentityQueryPort`，候选模块不直接依赖 IAM Model/Repository。
- 五个独立 Resolver 与 `CandidateResolverRegistry`，没有集中式类型 `if/elif`。
- `CandidateRule` 必填字段校验、未知类型错误和重复 Resolver 注册保护。
- 所有查询过滤停用用户、停用成员关系、停用组织以及停用角色/岗位。
- Resolver 统一返回 `set[int]`，跨组织重复用户自动去重。
- 只读人工演示入口：`python -m app.demo.candidate_demo`。

本轮没有新增数据库表或 Alembic 迁移，也没有提前实现 WorkflowTask、WorkOrder 或状态机。

## 回归覆盖

| 用例 | 输入 | 结果 |
| --- | --- | --- |
| CAN-001 | ORG_ROLE(管网运行部, REPAIRER) | `lisi`、`zhaoliu` |
| CAN-002 | ORG_ROLE(调度中心, REPAIRER) | 空集合 |
| CAN-003 | ORG_POSITION(管网运行部, DEPT_MANAGER) | `zhangsan` |
| CAN-004 | USER(停用用户) | 空集合 |
| CAN-005 | 同一用户在两个组织拥有同一角色 | 结果只出现一次 |

另外覆盖五类 Registry 完整性、ORG 精确成员范围、停用成员关系过滤、缺少必填字段和未知类型。

## 前五轮人工验收

### 1. 启动服务

```powershell
.\.venv\Scripts\python.exe -m alembic upgrade head
.\.venv\Scripts\python.exe -m app.iam.seed
.\.venv\Scripts\python.exe -m uvicorn app.main:app --port 8000
```

打开 <http://127.0.0.1:8000/docs>，使用 `wangwu / Demo@123456`：

1. 调用 `POST /auth/login`，应返回 `DISPATCHER`、`REVIEWER` 和 5 项工单权限。
2. 调用 `GET /auth/me`，应看到 `DISPATCH_CENTER` 与 `PIPE_OPERATION` 两个组织。
3. 将 active-org 切到 `PIPE_OPERATION`，角色和权限应变为空。
4. 尝试切换到非成员组织，应返回 403。
5. 调用退出，再访问 `/auth/me` 应返回 401。

### 2. 观察五类候选人

```powershell
.\.venv\Scripts\python.exe -m app.demo.candidate_demo
```

预期关键结果：

- USER → `lisi`
- ROLE(REPAIRER) → `lisi`, `zhaoliu`
- ORG(PIPE_OPERATION) → `wangwu`, `zhangsan`, `lisi`, `zhaoliu`
- ORG_ROLE(PIPE_OPERATION, REPAIRER) → `lisi`, `zhaoliu`
- ORG_POSITION(PIPE_OPERATION, DEPT_MANAGER) → `zhangsan`

### 3. 验证停用过滤与去重边界

```powershell
.\.venv\Scripts\python.exe -m pytest tests/test_candidate_resolvers.py -v
```

专项测试会在隔离数据库中验证停用用户/成员关系不会被返回，以及同一用户跨组织重复命中时只返回一次，不修改演示数据库。
