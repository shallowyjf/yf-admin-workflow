# I06：WorkOrder 领域

## 本轮目标

实现工单主表、业务动作日志、创建/提交、业务编号、列表/详情/时间线 API，并把 I03 的结构化 DataScope 真正转换为 Repository SQL 条件。

## 已实现

- `wo_work_order`：设计约定的编号、来源、优先级、组织、办理人、状态、资产、位置和时间字段。
- `wo_action`：记录 CREATE、SUBMIT 的操作人、前后状态、备注和扩展载荷。
- `WorkOrderNumberService`：生成 `WO + YYYYMMDD + 4位流水`，编号不在 Router 拼接。
- `WorkOrderService.create/submit/list_visible/get_visible/timeline`。
- 创建原子写入 DRAFT 工单及 CREATE 日志；提交原子写入 `DRAFT → PENDING_DISPATCH` 和 SUBMIT 日志。
- 提交只允许创建人执行；重复提交返回 409。
- 列表、详情和时间线先验证 `workorder:view`，再应用 ALL、组织集合和 SELF SQL 条件。
- 不可见详情统一返回 404，避免泄露对象是否存在。
- `POST /api/workorders`、`POST /api/workorders/{id}/submit`、列表、详情和时间线 API。

## 状态边界

I06 只开放 CREATE 和 SUBMIT。状态只能由 WorkOrder 领域方法修改；Router、Service、Repository 均不能直接赋值。派单、认领、处理、复核和关闭仍属于 I08。

I06 提交后暂时只形成 `PENDING_DISPATCH` 工单，不创建流程实例或任务。`WORK_ORDER_STANDARD`、WorkflowInstance 和 WorkflowTask 属于 I07。

## 数据库迁移

- 新增 `0005_i06`。
- 新增 `wo_work_order`、`wo_action`。
- 支持从 head 回退到 `0004_i04` 并完整移除两张表。

## 回归覆盖

- 同日连续创建生成 `0001`、`0002` 编号。
- 创建同步写 CREATE 日志。
- 创建人提交成功并写 SUBMIT 日志；非创建人被拒绝；重复提交返回 409。
- 没有 `workorder:create` 的用户返回 403。
- 空白标题在 Service 层也被拒绝。
- Repository 对 ORG、ORG_AND_CHILD 的组织集合和 SELF 创建人/办理人执行真实 SQL 过滤。
- SYSTEM_ADMIN 的 ALL 可见全部，普通用户只能看到自己的 DataScope。
- 未登录返回 401；不可见详情返回 404；时间线顺序正确。
- 架构检查保证 Router、Service、Repository 不直接赋值 `status`。

## 人工验收

1. 打开 <http://127.0.0.1:8000/docs>。
2. 使用 `wangwu / Demo@123456` 调用 `/auth/login`。
3. 调用 `POST /api/workorders`：

```json
{
  "title": "DMA 分区压力异常",
  "type": "DMA_PRESSURE_ANOMALY",
  "priority": "HIGH",
  "location": "城北 DMA",
  "description": "夜间最小流量异常"
}
```

4. 返回状态应为 `DRAFT`，编号格式应为 `WOYYYYMMDD0001`。
5. 调用 `POST /api/workorders/{id}/submit`，请求体 `{}`，状态应变为 `PENDING_DISPATCH`。
6. 查询列表、详情和 timeline；时间线应依次为 CREATE、SUBMIT。
7. 以 `lisi` 登录：创建应返回 403，列表看不到王五未分配给自己的工单，详情返回 404。
8. 以 `admin` 登录：列表可以看到全部工单。
