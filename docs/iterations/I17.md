# I17：SLA、附件与站内通知

## 变更摘要

本轮完成 P1 第二个业务产品迭代。新工单按优先级生成响应和解决时限；管理员可幂等执行 SLA 检查并产生超时动作。可见用户按权限上传、查询和下载已通过安全检查的附件。转派、催办和 SLA 超时进入个人通知收件箱，并支持已读回执与失败重试状态。

## SLA

- `URGENT`：24X7，10 分钟响应、60 分钟解决。
- `HIGH`：工作日 09:00–18:00，30 分钟响应、240 分钟解决。
- `NORMAL`：工作日 09:00–18:00，60 分钟响应、480 分钟解决。
- 周末和非工作时段自动顺延；重复执行检查不会重复产生超时动作和通知。
- 新增 `workorder:sla:evaluate` 权限，按 DataScope 检查。

## 附件

- 支持 PDF、PNG、JPEG、UTF-8 TXT，单文件不超过 5 MiB。
- 校验扩展名、MIME、魔数/文本编码，拒绝可执行文件和扫描命中内容。
- 保存 SHA-256 与 `CLEAN` 扫描状态，下载响应设置 `nosniff`。
- 上传记录 `ATTACHMENT_UPLOAD` 工单动作；列表和下载再次执行数据范围鉴权。

## 通知

- 转派通知新处理人，催办通知当前处理人，SLA 超时通知当前处理人或创建人。
- 收件箱严格按当前用户过滤，支持已读时间；失败记录保留错误和重试次数。
- 页面导航显示未读数量。

## 数据库与依赖

- Alembic `0008_i17` 新增 `wo_sla_policy`、`wo_attachment`、`sys_notification`，并为工单增加 SLA 字段。
- 新增官方 `python-multipart 0.0.32` 依赖处理流式表单上传。
- 默认 SLA 策略由 `python -m app.workorder.seed` 幂等初始化。
