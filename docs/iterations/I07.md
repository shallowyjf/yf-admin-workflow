# I07：流程实例与待办任务

## 本轮目标

让已提交工单真正进入流程中心：固定发布一版 `WORK_ORDER_STANDARD`，创建流程实例、首个人工任务、候选人快照和任务创建历史，并提供登录用户的“我的任务”查询。

## 已实现

- 新增 `wf_definition`、`wf_instance`、`wf_task`、`wf_task_candidate`、`wf_task_history` 五张表及 I07 迁移。
- `python -m app.workflow.seed` 幂等发布 `WORK_ORDER_STANDARD` v1。
- `start_for_workorder` 保证一张工单只有一个运行实例。
- `create_task` 保存原始 CandidateRule，同时把当时解析出的有效用户固化为候选人快照。
- 提交工单、创建流程实例和首个 `DISPATCH` 待办共用同一事务。
- `GET /api/tasks/mine` 同时支持候选人任务和已分配任务查询。
- 每个任务创建时记录 `CREATE` 历史；认领、完成和退回历史在对应动作实现后写入。

## 人工验收

1. 使用 `wangwu / Demo@123456` 登录。
2. 创建一张工单，确认状态为 `DRAFT`。
3. 提交工单，确认状态变为 `PENDING_DISPATCH`。
4. 请求 `GET /api/tasks/mine`，确认出现同一工单的 `DISPATCH / PENDING` 待办。
5. 确认 `assignee_id` 为空、`is_candidate=true`，表示它尚未被认领。
6. 退出登录后再次请求“我的任务”，确认返回 401。

## 本轮边界

I07 只负责启动流程、创建任务和查询待办。任务认领、并发保护、任务访问判定、完成/退回以及工单后续状态迁移均属于 I08，当前不能人工测试这些动作。
