# I21：系统入口与项目授权闭环

## 目标

在 I20 只读项目展示基线上，补齐用户系统入口、活动系统/项目会话、项目配置和项目级角色授权，使租户、系统、项目、组织和角色五个维度形成可执行的服务端授权链。

## 本轮完成

- 新增 `sys_user_application`，显式配置用户可进入的生命线系统；
- 认证会话新增 `active_application_id` 和 `active_project_id`；
- `/auth/me` 返回可选系统、可选项目和当前活动上下文；
- 增加系统/项目 API 与页面切换，非法系统或项目返回 403；
- 项目支持列表、详情、新建、编辑、归档状态和空项目安全删除；
- 项目参与组织支持原子替换，必须且只能配置一个甲方牵头组织；
- 项目成员角色支持原子替换，成员必须来自参与组织或其下级组织；
- 项目成员角色必须具备系统查看和项目查看权限，项目至少保留一个管理角色；
- 项目操作同时校验组织功能权限、系统入口、项目成员资格和项目角色权限；
- 增加授权链解释接口，返回每个判定条件、匹配角色和最终结果；
- 系统入口或活动项目成员资格撤销后，旧会话下一次请求立即失效；
- `/lifeline` 增加系统/项目选择器和项目、参与组织、成员角色配置表单。

## 核心接口

- `POST /auth/active-application`
- `POST /auth/active-project`
- `GET/POST /api/lifeline/projects`
- `GET/PUT/DELETE /api/lifeline/projects/{id}`
- `PUT /api/lifeline/projects/{id}/organizations`
- `PUT /api/lifeline/projects/{id}/members`
- `GET /api/lifeline/projects/{id}/authorization-explain`
- `PUT /api/lifeline/users/{id}/applications`

## 自动化回归

1. 用户只能切换到已授权系统和可见项目；
2. 跨系统或非成员项目切换返回 403，原会话上下文不被扩大；
3. 管理员可创建项目并完成四方组织、项目成员和项目角色配置；
4. 已有关联的项目不能物理删除，只能归档；
5. 授权链解释可精确返回系统入口、成员资格、角色权限和组织功能权限；
6. 移除活动项目成员后，其旧会话下一次请求返回 401；
7. 撤销活动系统入口后，其旧会话下一次请求返回 401；
8. 跨租户同编码项目、系统入口和项目查询保持隔离；
9. I01–I20 IAM、工作流和工单回归全部继续通过。

## 人工验收

1. 使用 `admin / Demo@123456` 登录 `/lifeline`；
2. 在顶栏切换供水、排水、燃气、供热、道路系统和对应项目；
3. 新建一个测试项目，配置甲方牵头方、监管方、施工方、平台方；
4. 配置至少一个系统管理员/甲方领导/施工项目经理角色成员；
5. 在 `/docs` 调用授权链解释接口，确认每个条件清晰可读；
6. 使用 `lisi` 登录，只能选择供水、排水、供热及本人参加项目；
7. 管理员撤销 `lisi` 的当前项目成员或供水入口，原登录会话应立即失效。
