# I12：用户生命周期与多组织关系

## 1. 变更摘要

用户管理从只读视图升级为生命周期和成员关系配置闭环。系统管理员可以通过 REST API 或页面新增、编辑、启停用户，重置密码，并整套配置用户的多组织关系、唯一主组织、组织内角色和岗位。所有成功写操作写入 I11 建立的 IAM 审计日志。

## 2. 新增/修改文件

- 新增 `app/iam/user_admin_service.py`：用户生命周期、多组织关系、权限校验和审计。
- 新增 `app/iam/user_router.py`：用户 REST API。
- 扩展 IAM Schema/Repository：用户与嵌套成员关系响应、关系替换查询。
- 扩展 Auth Repository/Service：提供事务内批量会话撤销端口。
- 修改 Dashboard Router/Service、用户模板和 IAM 样式：页面管理动作。
- 新增 `tests/test_user_admin.py`，扩展页面、Seed、健康检查回归。

## 3. 数据库迁移说明

本轮没有数据库结构变化，不新增 Alembic Revision。角色、岗位继续通过 `sys_user_org_role`、`sys_user_org_position` 绑定 `sys_user_org`；没有新增 `user.org_id`、`user.role_id` 或 `user.position_id`。

Seed 新增以下权限，并且只授予 `SYSTEM_ADMIN`：

- `system:user:create`
- `system:user:update`
- `system:user:status`
- `system:user:password`
- `system:user:membership`

## 4. 公开 Service/API 变化

- `GET /api/users`：用户及嵌套成员关系列表。
- `GET /api/users/{id}`：用户详情。
- `POST /api/users`：新增用户。
- `PUT /api/users/{id}`：编辑姓名和手机号码。
- `POST /api/users/{id}/status`：启停用户。
- `POST /api/users/{id}/password`：管理员重置密码。
- `PUT /api/users/{id}/memberships`：整套替换组织、主组织、角色和岗位配置。

用户名创建后保持稳定；用户不提供物理删除。成员配置必须至少包含一个组织且恰好有一个启用的主组织。停用用户、重置密码或替换成员关系后，目标用户全部现有 Session 立即撤销。

## 5. 测试清单与执行结果

```powershell
.\.venv\Scripts\python.exe -m pytest -W error
.\.venv\Scripts\python.exe -m ruff check app tests migrations
.\.venv\Scripts\python.exe -m alembic check
```

专项回归覆盖：

- 同一用户在两个组织拥有不同角色和岗位。
- 切换 active_org 后有效权限随组织变化。
- 停用成员关系后权限和 CandidateResolver 同时失效。
- 主组织唯一性、重复组织、无效角色岗位等输入约束。
- 密码重置、用户停用和成员变更后的 Session 撤销。
- 页面全生命周期配置和非管理员 API/页面越权拒绝。

本轮全量结果：`95 passed`，Ruff 与 Alembic 一致性检查通过。

人工验收：使用 `admin / Demo@123456` 打开 <http://127.0.0.1:8000/iam/users>，创建临时用户，为其配置调度中心 `DISPATCHER` 和管网运行部 `REPAIRER`，分别切换组织验证权限；再执行重置密码和停用，确认旧会话与登录均失效。

## 6. 与设计文档是否存在偏差

没有修改核心 User–Organization–Role–Position 模型。用户“删除”采用停用替代，原因是用户被认证会话、工单、任务和审计记录引用；该约束与保留历史可追溯性的设计目标一致。

## 7. 遗留问题

角色 Permission/DataScope 仍为 Seed 初始化和只读展示，安排在 I13；岗位和权限字典维护安排在 I14。本轮不提前实现。
