# I14：岗位、权限字典与 IAM 审计联调

## 1. 变更摘要

岗位和 Permission 字典从只读展示升级为管理闭环，并新增 IAM 审计查询视图。至此组织、用户、角色、岗位、权限五类 IAM 配置均可通过 REST API 和页面完成，所有关键写操作统一进入 IAM 审计日志。

## 2. 新增/修改文件

- 新增 `app/iam/dictionary_admin_service.py`：岗位、Permission 字典和审计查询用例。
- 新增 `app/iam/dictionary_router.py`：岗位、Permission 与 IAM 审计 REST API。
- 新增 `app/iam/permission_catalog.py`：Seed 与管理服务共享的内置稳定权限目录。
- 扩展 IAM Model/Repository：审计操作人关系、组合过滤和字典聚合查询。
- 扩展 Workflow Repository：扫描流程定义、任务和候选快照中的岗位编码引用。
- 修改 Dashboard Router/Service、岗位和权限模板，新增审计模板。
- 新增 `tests/test_dictionary_admin.py`，扩展页面、Seed 和健康检查回归。

## 3. 数据库迁移说明

本轮没有数据库结构变化，不新增 Alembic Revision。`IAMAuditLog.operator` 仅为现有外键增加 ORM 关系；岗位流程引用保护通过扫描现有 JSON 字段完成。

Seed 新增以下权限，并且只授予 `SYSTEM_ADMIN`：

- `system:position:create/update/status/delete`
- `system:permission:create/update/delete`
- `system:audit:view`

## 4. 公开 Service/API 变化

岗位：

- `GET /api/positions`、`GET /api/positions/{id}`
- `POST /api/positions`、`PUT /api/positions/{id}`
- `POST /api/positions/{id}/status`
- `DELETE /api/positions/{id}`

Permission 字典：

- `GET /api/permissions`、`GET /api/permissions/{id}`
- `POST /api/permissions`、`PUT /api/permissions/{id}`
- `DELETE /api/permissions/{id}`

审计：

- `GET /api/iam/audit-logs`：支持 `entity_type`、`entity_id`、`action`、`operator_username`、`offset` 和 `limit`。

岗位和 Permission 编码创建后不可修改。岗位在存在用户组织绑定或流程 JSON 引用时不能删除；内置 Permission 永远不可删除，自定义 Permission 在角色授权或 DataScope 仍有引用时不能删除。

## 5. 测试清单与执行结果

```powershell
.\.venv\Scripts\python.exe -m pytest -W error
.\.venv\Scripts\python.exe -m ruff check app tests migrations
.\.venv\Scripts\python.exe -m alembic check
```

专项回归覆盖：

- 岗位新增、编辑、启停、安全删除和审计。
- 岗位停用后 CandidateResolver 下一次解析即时失效。
- 用户组织绑定、流程定义、任务和候选快照引用保护。
- Permission 新增、描述维护、角色引用保护、撤销清理后删除。
- 内置稳定 Permission 删除保护。
- IAM 审计按实体、ID、动作和操作人组合过滤。
- 业务角色只获得显式授予的 IAM 能力。
- REST API、六个 IAM 页面及非管理员越权拒绝。

本轮全量结果：`106 passed`，Ruff 与 Alembic 一致性检查通过。

人工验收：使用 `admin / Demo@123456` 分别打开 <http://127.0.0.1:8000/iam/positions>、<http://127.0.0.1:8000/iam/permissions> 和 <http://127.0.0.1:8000/iam/audit>，创建临时岗位和自定义权限，执行编辑、启停和删除，再按操作人 `admin` 过滤审计记录。

## 6. 与设计文档是否存在偏差

没有修改核心关系模型。岗位删除保护额外覆盖了无外键约束的流程 JSON 引用；Permission 编码对内置和自定义条目都保持不可变，避免代码、角色授权和外部集成因改码静默失效。
