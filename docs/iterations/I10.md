# I10：Jinja2 + HTMX 演示页面

## 本轮目标

在 I09 标准 DMA 后端闭环之上制作可人工操作的轻量页面。页面用于演示权限、数据范围、候选任务和工单状态机，不引入新的前端工程或绕过领域服务。

## 已实现的 10 个核心视图

1. 登录：演示账号登录、错误提示和退出。
2. 工作台：可见工单统计、个人任务、最近流转与工单入口。
3. 组织管理：组织编码、层级路径和启停状态。
4. 用户管理：用户在组织内的角色、岗位关系。
5. 角色管理：角色权限和 DataScope 汇总。
6. 岗位管理：岗位字典和绑定关系数量。
7. 权限管理：稳定权限编码字典。
8. 工单列表：按 DataScope 过滤的工单与有权用户的新建入口。
9. 工单详情：基本信息、当前任务、完整时间线和当前可执行动作。
10. 我的任务：候选任务、已认领任务和认领入口。

## 权限与流程约束

- 新增五个系统查询权限：`system:org:view`、`system:user:view`、`system:role:view`、`system:position:view`、`system:permission:view`，默认只授予系统管理员。
- 页面导航和动作集合在 `DashboardService` 中按当前有效权限、数据范围、工单状态和任务关系计算，模板不写稳定权限编码判断。
- 按钮隐藏仅改善用户体验；表单提交仍调用原有 WorkOrderService 与 WorkflowService，后端再次校验权限、DataScope、候选人和状态迁移。
- 无会话自动跳转登录页；无权限、数据校验失败、状态冲突和工单不存在均返回中文友好错误页及正确 HTTP 状态。
- 页面使用 Jinja2 服务端渲染，HTMX 负责渐进增强；没有 JavaScript 或外部 CDN 时标准链接与表单仍可工作。

本轮没有数据库结构变化，不新增 Alembic Revision，也不提前实现 I11 质量门禁。

2. 使用 `wangwu / Demo@123456` 登录，在工单中心创建工单，打开详情后提交并派给“管网运行部”。

4. 再使用 `wangwu` 登录，从详情复核通过并关闭。
5. 确认最终显示“已关闭”，时间线按顺序包含 `CREATE → SUBMIT → DISPATCH → CLAIM → SUBMIT_RESULT → APPROVE → CLOSE`。
6. 使用 `lisi` 直接打开 `/iam/users`，确认显示中文无权限提示；工单列表不显示新建按钮。
