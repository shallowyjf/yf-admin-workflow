# I16–I20：P1 可用业务产品优先路线

## 调整原则

根据产品决策，后续五轮先完成可感知、可操作、可验收的 P1 业务能力。P0 安全、并发与生产运维缺口继续保留为真实上线硬门槛，本路线不宣称替代它们。

## I16：工单协作核心

状态：已完成。

- 处理中工单转派，目标限定为当前组织有效处理人。
- WorkOrder 与 WorkflowTask 处理人原子同步。
- 协作评论和在途催办，统一进入工单时间线。
- `workorder:comment`、`workorder:urge` 稳定权限和数据范围。

## I17：SLA、附件与通知

状态：已完成。

- SLA 规则、响应/解决时限、24X7/工作日历和幂等超时升级。
- 附件内容与元数据、类型/大小/签名约束、下载鉴权和安全扫描端口。
- 站内通知、已读回执、失败重试状态和事件留痕。

## I18：列表与运营效率

状态：已完成。

- 工单和 IAM 服务端分页、组合搜索、排序及保存视图。
- 工单批量派单/催办与权限逐条校验。
- 组织、用户和角色授权批量导入导出及错误报告。

## I19：租户与实体组织基线

状态：已完成。原计划的流程配置治理根据智慧城市 SaaS 产品决策顺延。

- 租户主数据、租户内唯一 IAM 编码和认证租户上下文。
- 用户、组织、角色、岗位、IAM 审计和会话租户归属。
- IAM 管理查询、流程角色候选人和跨租户对象访问隔离。

## I20：项目数据权限载体

状态：待开始。后续权威路线以 `PERMISSION_WORKORDER_REQUIREMENTS.md` 为准。

- 项目、项目参与组织、项目成员、项目角色和项目资源范围。
- 项目数据范围解析、活动项目和授权链解释基础。
- 项目 CRUD、成员维护和跨项目隔离回归。
