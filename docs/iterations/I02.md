# I02 IAM 基础模型

## 变更摘要

实现 User、Organization、Role、Position、UserOrganization，以及组织内角色和岗位关系。组织树和 Seed 均通过 IAM Service 驱动，不包含 Permission、登录或候选人解析。

## 新增与修改文件

- `app/iam/models.py`：7 张 IAM 基础表。
- `app/iam/repository.py`：IAM 查询与持久化。
- `app/iam/service.py`：组织、用户、成员、角色和岗位用例。
- `app/iam/seed.py`：设计资料规定的幂等 Seed。
- `migrations/versions/0002_i02_iam_foundation.py`：I02 升降级迁移。
- `tests/test_iam_*.py`：关系、组织树、Seed 和约束回归。

## 数据库迁移

- 新增 `sys_user`、`sys_org`、`sys_role`、`sys_position`。
- 新增 `sys_user_org`、`sys_user_org_role`、`sys_user_org_position`。
- `sys_user_org` 唯一约束为 `(user_id, org_id)`。
- 角色和岗位关系分别约束 `(user_org_id, role_id)` 与 `(user_org_id, position_id)`。

## 公开 Service/API 变化

- 新增 `IAMService` 的用户、组织、角色、岗位和成员关系操作。
- 新增 `IAMService.organization_tree()`。
- 本轮无新增 HTTP API。

## 测试清单

1. 用户可属于两个组织，角色只在指定组织生效。
2. User 不存在 `org_id` 或 `role_id`。
3. Service 与数据库约束均阻止重复成员关系。
4. 组织树保持父子关系和排序。
5. Seed 重复执行不产生重复记录。
6. 李四、赵六在管网运行部具有 REPAIRER；张三具有 DEPT_MANAGER。
7. I02 迁移可升级并回退到 I01。

## 与设计文档的偏差

`sys_user_org` 增加 `is_active`，依据详细设计的公共启停字段和“启用组织关系才能成为候选人”领域不变量，为 I05 留出明确状态位；未实现任何候选人逻辑。
