# I04：登录与 RequestContext

## 本轮目标

实现安全密码哈希、登录 Session、当前用户依赖和活动组织切换。登录身份与当前操作组织分离；切换组织后重新计算角色和权限。

## 已实现

- 基于标准库 `scrypt` 的随机盐密码哈希和恒定时间校验。
- 数据库端 `sys_auth_session`：保存令牌摘要、当前组织、有效期和注销时间；原始随机令牌只写入 Cookie。
- `yf_session` Cookie：`HttpOnly`、`SameSite=Lax`，生产环境可通过配置启用 `Secure`。
- `RequestContext(current_user_id, active_org_id, session_id)`。
- `POST /auth/login`、`POST /auth/logout`、`GET /auth/me`、`POST /auth/active-org`。
- 切换目标必须是当前用户的有效组织关系；切换后角色和权限从数据库重新计算。
- Seed 用户密码从 I03 禁用占位值幂等升级为安全哈希。
- `wangwu` 增加第二组织关系，用于验证同一用户在不同组织的独立权限上下文。

## 设计说明

详细数据库设计未定义 Session 表，但 I04 明确要求 Session、注销和 `session_id`。本轮增加最小 `sys_auth_session`，以支持服务端失效、退出撤销和不把权限写进 Cookie；没有引入 JWT 或权限缓存。

## 回归覆盖

- 密码哈希随机加盐、正确密码通过、错误密码失败。
- 未登录访问 `/auth/me`、退出或切换组织均返回 401。
- 登录 Cookie 包含 `HttpOnly` 和 `SameSite=Lax`。
- `/auth/me` 返回当前组织、全部有效成员组织、当前角色与权限摘要。
- 合法组织切换成功并重新计算角色/权限。
- 非成员组织切换返回 403，原上下文保持不变。
- 退出后数据库 Session 被撤销，旧 Cookie 再访问返回 401。
- `0004_i04` 可独立升级和回退。

## 第 5 轮完成后的人工测试边界

I05 完成后，人工可以测试：

1. 在 Swagger 中用五个 Seed 账号登录、查看本人信息和退出。
2. 使用 `wangwu` 在 `DISPATCH_CENTER` 与 `PIPE_OPERATION` 间切换，观察角色及权限摘要变化。
3. 尝试切换到非成员组织，确认返回 403；清除 Cookie 或退出后确认返回 401。
4. 使用 I05 提供的候选人演示入口，验证 USER、ROLE、ORG、ORG_ROLE、ORG_POSITION 五类规则，并观察停用过滤和去重结果。
5. 对照 pytest 回归结果检查 ORG、ORG_AND_CHILD、SELF 数据范围规则。

第 5 轮后仍不能人工测试：真实工单列表/详情与数据范围过滤、派单认领、流程任务、状态机、DMA 闭环和 HTML Dashboard。这些分别属于 I06、I07-I09、I10。
