# 第一轮：运营总览与 DMA 异常处置

## 目标

用一个可运行的页面验证供水信息化平台的首个最小闭环：运营人员能够查看全域核心指标，定位异常 DMA 分区，查看告警详情，并把待确认事件推进到处理中。

## 设计依据

- 平台底座应先统一入口、指标口径和数据展示。
- DMA 是漏损控制从“看见异常”走向“分区运营”的核心组织单元。
- 生产调度与告警处置需要形成工作台，而非只做大屏展示。
- 第一轮先验证业务信息架构和交互闭环，不接真实 GIS、物联网或持久化数据库。

## 本轮交付

- FastAPI 本地服务与健康检查接口。
- 全域/四个 DMA 分区切换。
- 供水量、漏损率、压力、告警、在线率指标。
- 24 小时流量/压力趋势切换。
- 管网一张图示意与异常分区定位。
- 告警事件列表、详情和确认处置动作。
- 桌面、平板和手机响应式布局。

## 回归验收

1. 首页可访问，包含指标、一张图、趋势和事件工作台。
2. 健康检查返回版本 `0.1.0` 和迭代号 `01`。
3. 全域供水量等于四个 DMA 供水量合计。
4. 选择东城 DMA 后，指标和事件只显示东城数据。
5. 不存在的 DMA 返回 404。
6. 待确认事件能够进入处理中，并记录操作人。
7. 重复确认同一事件不会覆盖首次操作人。
8. 非法操作人参数返回 422。
