# I22：项目工单与流程闭环

## 目标

把 I21 的项目授权空间接入工单和工作流运行时，使业务数据不再只依赖组织范围，而是同时受租户、生命线系统和工程项目约束。

## 本轮完成

- `wo_work_order`、`wf_instance`、`wf_task` 增加非空 `tenant_id/application_id/project_id`、外键和组合索引；
- 增量迁移将历史工单及流程运行数据归入默认供水管网更新项目；
- 工单创建自动固化当前会话项目上下文，响应显式返回三个归属字段；
- 工单列表、搜索、详情和我的任务只查询当前租户、系统、项目；
- 提交、派单、认领、处理、转派、复核、关闭、协作、SLA 和附件继续校验组织功能权限，并叠加系统入口、项目成员角色及项目状态；
- 工作流实例和后续任务继承工单上下文；
- 组织/角色候选人解析结果与项目有效成员及项目角色权限取交集；
- 转派目标必须同时是当前组织处理人和当前项目有效处理成员；
- 归档、暂停项目允许查看历史工单，但禁止新增或继续变更；
- 未初始化项目目录的老单元测试保留兼容路径；一旦存在项目目录即启用严格项目校验。

## 自动化回归

1. 创建工单的三个上下文字段与当前认证会话完全一致；
2. 切换到另一项目后，原项目工单不进入列表，详情不可见，变更请求返回拒绝；
3. 组织角色候选人若不是当前项目成员，不会进入流程任务候选人快照；
4. 工作流实例、处理任务与工单项目上下文一致；
5. 项目归档后历史工单仍可查看，提交等写操作返回 403；
6. I01–I21 的 UI、API、IAM、工作流、工单、SLA、附件和并发认领回归继续通过；
7. 空库迁移、历史库升级、Alembic 漂移、Ruff、Warnings-as-errors 和覆盖率门禁继续执行。

## 人工验收

1. 用 `wangwu / Demo@123456` 登录，在供水项目创建一张工单；
2. 在工单详情或 `/docs` 确认 `tenant_id/application_id/project_id`；
3. 切换到排水项目，供水工单应从列表消失，直接访问也不能越权读取；
4. 切回供水项目，提交并派给管网运维部门；
5. 用 `lisi` 登录供水项目，可看到并认领任务；切换排水项目后看不到该任务；
6. 用管理员把供水项目归档，确认工单只读且所有写操作被拒绝。
