# I19：租户与实体组织基线

## 目标

为智慧城市 SaaS 增加可验证的租户隔离基线，同时保持实体组织、多组织成员关系、角色岗位、权限范围和既有工单流程兼容。

## 本轮完成

- 新增 `sys_tenant` 租户主数据和默认 `DEMO` 演示租户。
- 用户、组织、角色、岗位、IAM 审计和认证会话增加 `tenant_id`。
- 用户名、组织编码、角色编码和岗位编码改为租户内唯一。
- 登录接口支持可选 `tenant_code`，未传时使用配置的默认租户。
- 请求上下文和 `/auth/me` 返回租户 ID、编码和名称。
- 用户、组织、角色、岗位、IAM 搜索与审计 Repository 支持租户作用域。
- IAM、工单权限解析和流程候选人依赖使用当前会话租户作用域。
- 登录页面显示租户编码，演示环境默认 `DEMO`。
- 增加 I19 Alembic 升降级、跨租户同名账号、列表隔离、对象隔离和跨租户组织切换回归。

## 兼容策略

- 迁移将现有 IAM 和会话数据归入 `DEMO` 租户。
- API 登录未传 `tenant_code` 时保持原有单租户行为。
- Permission 字典继续作为平台稳定字典，不按租户复制。
- 工单、流程和项目的显式 `tenant_id/project_id` 在 I20-I21 接入；I19 通过用户、组织和角色租户一致性维持现有业务兼容。

## 人工验收

1. 使用租户 `DEMO`、账号 `admin`、密码 `Demo@123456` 登录。
2. `/auth/me` 应显示 `tenant_code=DEMO`。
3. 用户、组织、角色和岗位管理页面只显示当前租户数据。
4. 使用不存在的租户编码登录应返回统一认证失败，不泄露用户名是否存在。
5. 活动组织切换不能切换到其他租户的组织。
